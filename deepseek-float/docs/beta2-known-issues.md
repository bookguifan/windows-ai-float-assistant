## 发行后端安全边界

- 旧自动复制入口始终关闭。新实验入口只在 Windows、Debug、显式 experimental-clipboard-fallback 且不含 custom-protocol 时才可授权。
- Release 或 custom-protocol 构建即使误启实验特性也保持禁用；配置、备份、IPC 和运行时授权不能更改编译期策略。
- 捕获调度、授权 epoch、snapshot、copy_chord、restore 均有后端检查。UI 灰显不是安全边界。
- UIA 优先，标准 Unicode Edit 精确消息读取不使用剪贴板；密码/非 Unicode/不支持控件、目标变化、过期请求安全拒绝。用户主动复制属于另一条明确操作路径，仍有上述 N05 缺陷。
- 构建禁用是可达性证明；WM_COPY 的未知来源仍需核定，不能从单条消息推导策略失效。若确认发行门禁失效、未经授权复制或敏感数据问题，立即停止合并推进。

## CI、合并与发布分开判断

CI 明确执行 selection_core、copy_engine、native_copy_proof、uia_strategy、release_selection_policy、native_selection_policy 集成目标，以及 --lib。需要真实桌面的 native-window 测试保留 ignored；忽略不是 PASS。还执行显式研究 Debug 策略与带实验特性的 Release 策略。必须核对新 run 的实际日志，不能只检查 workflow 文本。

当前唯一 workflow 对 main/master push 和 pull_request 运行，contents: read，无 Tag/Release/附件上传步骤；pnpm build 不是 pnpm release。推送或未来合并 main 不会由该 workflow 自动发布 Beta.2。若后来新增发布流程须重新审查。

版本号仍为开发基线 0.1.0；Beta.1 Tag、Release 和附件不变。Beta.2 的版本冻结、最终 EXE 来源、PE 隐私审查、许可输入映射及最终包验收尚未完成，不得将本次开发提交当成可发布产物。

开发合并条件：所有新 SHA 检查成功、上述问题完整披露、无已确认安全退化/敏感信息/自动发布风险、维护者单独授权。CI 或安全检查失败即停止。Beta.2 发布需要另行关闭发布阻断并明确批准，本轮无合并或发布授权。
